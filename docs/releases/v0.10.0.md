# v0.10.0

The **deadlined seat** release. Every actor turn now runs under a deadline —
**a timeout is a recorded failed turn, never a wedge** — and the seat layer
grows a custodial identity keypair, a durable bounded journal with per-consumer
cursors, and cross-runtime event portability. Alongside it, the **lifecycle
CLI** ships: `npx @agentback/cli@latest update` resolves your version window,
runs the migration registry (advisories for this release included), and bumps
the lockstep ranges.

## ✨ Highlights

### `agentback update` — the lifecycle CLI grows its third verb

`@agentback/cli` (bins `agentback`/`abc`) now carries `new`, `deploy`, and
**`update`**: resolve the installed lockstep version → run every migration in
the `(from, to]` window → bump ranges and reinstall, in that order — bumping
first would let a failed install strand the window. A `Migration` is a codemod
or an **advisory** (a migration with no `apply`); detection is static source +
config reads and never boots the app. Because the package is
lockstep-versioned, **`npx @agentback/cli@latest update` is the primary
invocation** — the latest CLI carries the advisories for the version you are
moving to, and it refuses to run when older than its target.

This release ships **three new advisories for its own window** (see the
breaking changes below): `actors-turn-deadline`, `actors-event-json`, and
`actors-redis-dedup-ttl`.

### Actors: the seat layer

- **Every turn is deadlined per seat class** — `'capability'` (default, 30s: a
  caller is waiting) or `'worker'` (10 min), an explicit `deadlineMs` always
  winning. The caller gets a typed `TurnTimeoutError`, the seat frees at once,
  the failed turn is recorded (journaling runtimes append the reserved
  `actor.turn.timeout` entry), and the timed-out `requestId` **stays
  retryable**. The turn is abandoned, not cancelled — it can never commit, on
  any runtime.
- **Custodial secp256k1 keypair at birth**, dormant until claimed
  (`takeCustody` proven by test); the event envelope now carries identity via
  a required `seatKeyId`.
- **`actors-redis` journal, bounded and resumable** — opt-in retention
  (`journal: {maxEventsPerIdentity}`) applied by the same `XADD` that appends;
  `SeatJournalConsumerHost` persists a **cursor per consumer id**, so a
  restart replays the gap, not the world. Delivery stays at-least-once; a
  cursor that retention outran is logged as a gap and resumed, never thrown.
- **Cross-runtime event portability** — a shared conformance suite now runs
  delivery + event JSON-portability across all three runtimes.

## ⚠️ Breaking changes

### `@agentback/actors`: every turn now has a deadline (headline)

Turns previously ran unbounded; **an actor that declares nothing gets 30
seconds**. Any existing `@actor`/`defineActor` whose command turns
legitimately run longer starts throwing `TurnTimeoutError` at 30s — nothing
commits, the seat frees, the failed turn is recorded. The fix is one line on
the definition:

```diff
  // A turn nobody is blocked on: 10 minutes.
- @actor('nightly-import', {state: ImportState})
+ @actor('nightly-import', {state: ImportState, seatClass: 'worker'})

  // …or name the number outright; an explicit deadlineMs always wins.
- @actor('checkout', {state: CartState})
+ @actor('checkout', {state: CartState, deadlineMs: 90_000})
```

Queue wait never counts against a turn. A timed-out `requestId` stays
retryable — a timeout is not a cached failure result. The turn is abandoned,
not cancelled: side effects it already performed still happened (the runtime
rolls back actor state, not the world). See
[docs/actor-model.md](../actor-model.md#turn-deadlines).
_`update` advisory: `actors-turn-deadline`._

### `@agentback/actors`: a turn's events must be plain, finite JSON

Redis persists `turn.events` via `JSON.stringify`; the in-memory runtimes via
`structuredClone`. The two disagree on `undefined`, `NaN`/`Infinity`, `Date`,
`BigInt`, functions, and non-plain objects — so an app tested in-memory could
commit events on Redis that silently differ from the ones its turns emitted.
Every runtime now validates each event **at commit, before anything is
written**, and rejects a non-JSON value naming the offending path
(`events[0].when`). Serialize when emitting:

```diff
  events: [
-   {type: 'Snapshotted', at: new Date()},
+   {type: 'Snapshotted', at: new Date().toISOString()},
  ],
```

`state` and `result` are unaffected. _`update` advisory: `actors-event-json`._

### `@agentback/actors-redis`: `dedupTtlSeconds` is validated at construction

A fractional or out-of-range value used to be accepted and then raise from
`EXPIRE` mid-commit; it now throws from the `RedisActorRuntime` constructor.
Whole seconds between `0` (no expiry) and `MAX_DEDUP_TTL_SECONDS` are
accepted. _`update` advisory: `actors-redis-dedup-ttl`._

### `@agentback/actors`: two compile-visible signature changes (no advisory)

The compiler reports both with an obvious fix, so neither carries an advisory:

- **`ActorEventStore.subscribe` accepts an async handler** — the handler type
  widened to `(event) => void | Promise<void>` so a rejection is caught and
  logged like a synchronous throw instead of escaping as an unhandled
  rejection. Compile break only for expression-bodied handlers that return a
  value (`subscribe(e => seen.push(e))` — `push` returns a number). The fix
  is braces.
- **`ActorDefinition` gained required `seatClass` + `deadlineMs`** — a break
  only for code building the definition object literal by hand (a custom
  runtime's fixture). `defineActor`, `@actor`, and every adapter fill them in.

### `@agentback/actors`: C0 control characters in an actor type or id are rejected

Runtimes key a seat on `type + U+0000 + id`, so a NUL inside a
caller-supplied id (a REST path param, an MCP tool arg) made two identities
share one seat's state, dedup, journal, and cursor. Such ids now throw at
validation naming the offending half; ordinary ids, punctuation included, are
unaffected.

## Known gaps

- On Redis the deadline stops at the commit boundary: once the commit script
  is issued, a stalled commit makes that one caller wait — the **seat** is
  still bounded by the lease-renewal cap, so the identity cannot wedge. In
  process there is no such gap (the commit is synchronous).
