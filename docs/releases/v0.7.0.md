# v0.7.0

The **multi-faced agentic access** release. The one `@tool` surface — already
projected to REST, MCP, and OpenAPI — grows three new faces: an **AI SDK agent**
that runs your own tools, an **operator CLI**, and a **read-only introspection
MCP** an agent can ground itself in. A console **agent dock** ties the last one
into a see-and-evolve loop. File storage gains **byte-range reads**, **`stat()`**,
**presigned uploads**, and a **40-backend adapter**.

## ✨ Highlights

### An agent that runs your tools — `@agentback/agents`

Project your registered `@tool` classes as an [AI SDK](https://ai-sdk.dev)
agent's **host-executed tools** — same Zod schemas, same dispatch. Every call
routes through `MCPServer.callTool`: validation, `@authorize` voters, metering
hooks, output validation.

- `toHostTools(app, {include})` — your `@tool` classes as an AI SDK `ToolSet`;
  `execute` returns the unwrapped, output-validated result and works pre-`start()`.
  Throws at projection time on include typos / duplicates / provider-illegal
  names / `confirm:` tools — those never project.
- `installAgent(app, {agent})` binds a **TRANSIENT** turn wrapper
  (`AgentBindings.AGENT`) that reads identity per turn (transport `REQUEST_AUTH`
  always wins), preflights quota before the model spends, emits one `'agent'`
  usage event per turn with tool-call `'mcp'` events sharing `meta.correlationId`,
  and destroys live sessions on `app.stop()`.

`ai` is an **optional peer dep**, loaded lazily. **You** bring the model,
credentials, and where turns are exposed — there is no auto-projected
`/agent/run`. Not `@agentback/actors` (state turns). See
[`examples/hello-agents`](../../examples/hello-agents) (mock model, zero creds)
and [docs/guides/agents.md](../guides/agents.md).

### An operator CLI — `@agentback/command`

`buildCli(app, {include})` turns registered `@tool` classes into a hand-runnable
command — `my-svc forecast --city Tokyo` — routing every invocation through the
same `callTool` pipeline as REST/MCP/agents. The `@tool` **is** the command; no
`.command()` builder to learn.

- **`argvToBundle`** coerces string argv off the emitted JSON Schema before
  `callTool` re-validates (booleans as `--verbose`/`--no-verbose`, arrays repeat,
  positional args supported).
- Output is the tool's **bare result** on stdout (the exit code carries
  success/failure); errors print an `AgentError` envelope to **stderr** + non-zero
  exit. `--format text|json|toon` (default by stdout TTY only — never sniffs `CI`),
  `--llms` manifest of the selected tools, `<cmd> --help` from the schema,
  streaming NDJSON.

Audience is a **human operator/scripter**, not agents (agents already have
lossless stdio MCP). `@toon-format/toon` is an optional peer. See
[`examples/hello-command`](../../examples/hello-command) and
[docs/proposals/cli-projection.md](../proposals/cli-projection.md).

### Ground an agent in the live app — `@agentback/introspection`

A **read-only** MCP server that projects the running app to any agent (your
terminal Claude Code, Cursor, an A2A peer). A small selector surface —
`inventory(kind?)`, `get({kind,id})`, `get_okf_bundle()` — wrapping the
explorers' read-only builders. **Read-only forever:** never invokes a route/tool,
never resolves a secret-bearing binding (only schema-tagged bindings resolve, to
their Zod object). The "see" half of the see-and-evolve direction. See
[`examples/hello-agent-console`](../../examples/hello-agent-console).

### The console agent dock — `@agentback/console-chat`

A right-column chat panel in `/console` that spawns an **ACP** (Agent Client
Protocol) coding agent as a subprocess and bridges it to the browser over
SSE + POST. Grounded at session start with an OKF brief + `IntrospectionTools`
as a live MCP surface the agent can query — so it **sees** the live app before it
**evolves** the source (editing files under an inline approve/deny permission
model). **Off by default** (`enabled: false`), **Node-host-only** (absent on
`EdgeRestApplication`), and hidden unless ≥1 agent is discovered on `PATH`. All
`/console/chat/*` endpoints require an authenticated principal. See
[docs/guides/agent-console.md](../guides/agent-console.md).

### File storage grows up — `@agentback/files` (+ `-s3`, `-sdk`)

- **Byte-range reads** — `get(key, {range})` reads a slice; `serveFile(store,
  key, {range})` (from `@agentback/rest`) wires the full HTTP `Range` →
  `206`/`416` path on both the Express and edge hosts, advertising
  `Accept-Ranges` only when the store's `supportsRange` allows (video seek,
  resumable downloads).
- **`stat(key)`** — metadata without transferring the body (the cheap HEAD path),
  on every adapter.
- **Presigned uploads** — `presignedPut` returns a `SignedUpload` (a `PUT` URL,
  or a size-enforced `POST` form when `maxSize` is set).
- **`@agentback/files-sdk`** — a `FileStore` adapter over
  [files-sdk](https://files-sdk.dev) backing the same port with **40+ storage
  backends** (S3, R2, GCS, Azure, Vercel Blob, fs, …); presign/range gated on the
  backend's advertised capabilities.

### Also

- **`@agentback/plugin`** — imperative `loadPlugin(app, specifier)` (idempotent)
  alongside the declarative discovery path; `examples/hello-plugin`.
- **`@agentback/console`** — live reflection: a `/live` SSE endpoint + `BOOT_ID`
  so the console reloads on a server restart, preserving selection.
- **Website** — a "Coming from another framework?" comparison page with
  per-framework side-by-side code, and a "why another framework" homepage beat.

## 🐛 Fixes

- **rest** — collapse duplicate slashes when joining `basePath` + route.
- **rest** — Range header parsing hardened to decimal-only (RFC 7233).
- **files** — `serveFile` honors `supportsRange`: never advertise a range it
  can't serve.
- **console-chat** — block `javascript:`/`data:` URLs in chat markdown links (XSS).
- **mcp** — re-export `AuthInfo` from `@agentback/mcp`.
