# v0.7.1

A maintenance release: the framework now **builds on the TypeScript 7 native
compiler**, tests on **Node 26**, and refreshes its dependency floor. No package
API changes — the compiled output is semantically identical to v0.7.0, so
consumers upgrade with nothing to react to.

## 🛠 Toolchain

### Builds on TypeScript 7 (native Go compiler)

`tsc -b` across the workspace now runs on TypeScript 7.0, cutting a cold build
from ~18s to ~3s. TypeScript 6 is installed **side-by-side** (per Microsoft's
[TS 7 guidance](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/))
so `@typescript-eslint` and editor language services — which need the JS compiler
API that TS 7 no longer ships — keep working:

- `tsc` → TypeScript 7 (fast builds)
- `require('typescript')` → TypeScript 6 (full API, for eslint + tsserver)

This is purely a build-time change. Published packages ship the same compiled
JS and `.d.ts`; **no consumer needs TypeScript 7**.

### CI on Node 26

The test matrix adds Node 26 alongside 22.13 and 24.

## 🐛 Fixes

- **`@agentback/mcp-http`** — read `req.auth` through a local cast instead of the
  MCP SDK's `express-serve-static-core` module augmentation. The augmentation is
  version-specific, so a split in `@types/express-serve-static-core` (which a
  dependency bump can introduce) would otherwise drop `req.auth` and break the
  build. Behavior is unchanged; the package no longer depends on the augmentation
  merging.

## 📦 Dependencies

Refreshed via `ncu` — notably `@typescript-eslint` 8.63, `prettier` 3.9.5,
`vitest` 4.1.10, `ai` 7.0.18, `fastify` 5.10, the `@aws-sdk/*` line, the ACP dock
adapters, and `pnpm` 11.10. `@types/node` stays on the active-LTS `^24` line.

## Upgrading

```bash
npm install @agentback/core@0.7.1   # …and any other @agentback/* packages
```

Lockstep as always — every `@agentback/*` package and `create-agentback` moves to
0.7.1 together.
